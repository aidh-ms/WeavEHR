# Working on WeavEHR

Use `uv sync --frozen --all-groups` for the development environment. Read the
relevant implementation and tests before changing or describing behavior.

## Documentation and comments

- Follow `docs/contributing/documentation.md` for audience, structure, and ownership.
- Follow `docs/contributing/comments.md` for comments, docstrings, and attribution.
- Update the canonical page; link to it instead of adding duplicate explanations.
- Keep the README short. Do not append feature-by-feature history there.
- Dataset and concept inventories are generated by `docs/scripts/gen_catalogue.py`.
  Do not hand-maintain their counts or edit generated `site/` output.
- Keep `example/quickstart/` runnable without external data. Update its documentation
  tests when examples change. Explain current behavior, not planned features.
- Preserve scientific rationale, upstream deviations, and required notices when
  simplifying comments. Put repeated source revisions in `configs/SOURCES.md`.
- Build documentation with `uv run mkdocs build --strict` and fix warnings.

## Code and configuration

Python 3.13+, typed public interfaces, Ruff formatting, and Conventional Commits.
Configurations use Pydantic; data transformations use Polars LazyFrames.
Registries are global: isolate them in tests. Never commit patient data.

Run relevant tests during iteration. Before a PR, run Ruff, `uv run ty check .`,
`uv run pytest`, and the strict docs build. For mappings, exercise synthetic inputs
and run `tests/test_shipped_configs.py`. See `docs/contributing/architecture.md`
for extension points and `docs/getting_started/contributing.md` for the workflow.
